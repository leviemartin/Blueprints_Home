Consumers read every instant as `state_attr(<helper>, 'timestamp') | float(0)` (the helper's own unix-seconds attribute; never `as_timestamp(states(...))`). **Record health (`record_ok`, R1-03, R2-08):** every helper the consumer is configured with exists in the state machine and is not `unavailable`; the stamp helper's `unknown` or empty state is a valid "no stamp"; the configured watcher automation (`watcher_automation` input on N and S; the `watcher` key of P's records) is `on`. A record that is not ok makes the consumer skip every command to that fan and raise one fixed-id notice (`…_record_missing`, message names which helper or the watcher); it never issues an unstamped command. **Record validity (`record_valid`, R2-06, D-T mitigation):** the parsed stamp and since pass the strict checks of C2; an invalid record is fail-closed exactly like a missing one, with its own notice (`…_record_invalid`) whose text gives the recovery: set the stamp helper to empty and, if the since helper is in the future, to a past instant; the helpers stay off dashboards.

### C2. Stamp format, validation and the per-fan transaction rule

```text
<writer>|<state>|<pct>|<dir>|<ts>|<txn>
writer ∈ {precool, daytime, seasonal}; state ∈ {on, off}; pct = integer 0..100 or *; dir ∈ {forward, reverse, *}; ts = unix seconds (int) at stamping; txn = unix seconds (int) of the first stamp of the transaction this stamp belongs to (txn == ts for a fresh transaction; a re-issue or a later phase of the same transaction repeats the original txn)
examples: precool|on|1|*|1790000000|1790000000   daytime|off|*|*|1790000600|1790000600   daytime|off|*|reverse|1790000660|1790000600 (direction phase of the transaction opened at ...600)
```

Strict validation (R2-06): exactly six `|`-separated fields; writer, state, dir from the sets above; pct `*` or digits 0..100; ts and txn all digits, `txn <= ts`, `ts <= now_ts + 60` (a future stamp is invalid, never "already written"); the since helper's timestamp `<= now_ts + 60` (a future since is invalid, never "manual"). Empty or `unknown` stamp helper = "no stamp" (valid). Anything else = invalid record (fail closed, C1). `*` means "not asserted".

Writer invariant ("no stamp, no command", R1-09, R2-07): immediately before every `fan.turn_on`, `fan.turn_off` and `fan.set_direction`, including its own safety cut and every re-issue, the writer (1) calls `input_text.set_value` on the fan's stamp helper with no `continue_on_error` and no `enabled: false` (a failed or rejected stamp, including a helper deleted between validation and stamping, aborts the run before the command), (2) reads the helper back in the same sequence and proceeds only if it now holds exactly the stamp just written, (3) commands. **Fresh-foreign veto:** a writer never stamps over another writer's stamp younger than `lag_seconds` (that command is in flight), except that its own pending stop (C3) is never a foreign stamp. **Transaction continuity:** every later phase or re-issue of a transaction first checks that the slot still holds its own writer and txn; otherwise it abandons the transaction (the newer writer owns the fan). **Ownership-preserving restore (S only):** S's restart stamp names the writer whose expectation it restores — the previous stamp's writer when that stamp was valid and matched the live fan before the flip (`precool` or `daytime`), else `seasonal` — so a seasonal flip mid-nap or mid-settle leaves the fan owned by N or P (example 20, 36). Writer-id ticks are de-phased (P at second 0, N at second 30) so the two tick-driven writers never evaluate the same fan in the same event-loop turn; residual viii covers the remaining state-triggered coincidence.

### C3. Consumer predicates (exact definitions; variable names are the test names' vocabulary)

- `record_ok`, `record_valid`: per C1/C2. Every fan predicate below is false when either is false.
- `since_ts`: the since helper's timestamp attribute, 0 when unset.
- `stamp_*`: parsed latest stamp (`stamp_writer`, `stamp_state`, `stamp_pct`, `stamp_dir`, `stamp_ts`, `stamp_txn`), or "no stamp".
- `stamp_matches`: the fan's live state equals `stamp_state`, and its live percentage equals `stamp_pct` when asserted. Direction is not part of ownership (a seasonal flip keeps a fan ours; direction correctness belongs to the direction phase). Direction is matched only by the watcher's own-write rule.
- `ours` (per writer W): `record_ok and record_valid and stamp_writer == W and stamp_matches and since_ts < stamp_txn`.
- `manual_in_window(start_ts)`: `since_ts >= start_ts`.
- `owned_by_other(ref_ts)`: `stamp_writer` is one of the other writers and `stamp_ts >= ref_ts`.
- `foreign_fresh`: `stamp_writer != W and now_ts - stamp_ts <= lag_seconds` (veto, C2).
- `already_written` (per writer): `stamp_writer == W and now_ts - stamp_ts <= lag_seconds`. A lost command is retried at most once per lag, never per tick; a landed command is idempotent through the "at target" checks.
- `manual_veto(txn)`: `since_ts >= txn` — a genuine manual change since the transaction opened; blocks every continuation, restore and re-issue of that transaction (R2-04).
- **`pending_stop` (per writer, the Class A rule):** `stamp_writer == W and stamp_state == 'off' and fan is on and as_timestamp(fan.last_changed) <= stamp_ts and not manual_veto(stamp_txn) and now_ts - stamp_txn < stop_deadline_seconds`. While pending: re-stamp `W|off|*|*|now|stamp_txn` and re-issue `fan.turn_off` when `now_ts - stamp_ts >= lag_seconds` (once per lag; a re-issue is allowed while interlock-blocked and inside any window, day or night, because it is an off). The obligation ends when the fan reads off, when a later transition supersedes it (`fan.last_changed > stamp_ts`, which M classifies on its own), or when a manual since supersedes it. **`stop_fault`:** the fan still on, `fan.last_changed <= stamp_ts`, `now_ts - stamp_txn >= stop_deadline_seconds` (240 = 2 × lag): one notice `…_stop_failed` (state-driven, dismissed when the fan reads off or at the next boundary), no further re-issue of that transaction, the fan left under the cutoff/manual regime and treated as not ours; a later due condition (vacancy-off, nap-end off, cut) may open a new transaction, each bounded the same way. The pending-stop evaluation is the first fan-related step of every tick in N and P (before any window gate, `stop:` or early exit) and the first thing S does after its own stop.
- **Direction phase deadline (R2-11):** a `W|off|*|<dir>|ts|txn` stamp means "set_direction issued at ts". The phase is issued once per transaction; `abort` = live direction ≠ `stamp_dir` and `now_ts - stamp_ts > direction_wait_seconds` (90) → one notice `…_reversal_aborted`, no re-issue, fan left off, and the aborted stamp (dir asserted, older than 90 s) blocks every start of that transaction's nap until the nap toggle cycles (`nap_on_ts > stamp_ts`). A `W|off|*|*` stamp (dir `*`) is a plain stop and never latches; the two are disjoint (R1-04).
- Interlock rule (kids instances, identical to pre-cool's `interlock_blocked`): blocked while any configured interlock sensor is `on`, `unavailable`, `unknown`, absent, or has `last_changed` within `interlock_clear_minutes` (5 ≥ cutoff hold 3 + 2). No `turn_on`, `turn_off` or `set_direction` while blocked, with two exceptions that are both offs: the writer's own safety cut (`cut_due`) and a `pending_stop` re-issue.
- `cut_due` (per writer, kids fan): fan on, `stamp_writer == W`, `stamp_state == on`, `now_ts - stamp_ts <= lag_seconds`, `as_timestamp(fan.last_changed) >= stamp_ts`, any interlock sensor reads `on` (and, for P, the fan is in `interlocked_fans`, R1-10) → stamp `W|off|*|*|now|now` then `turn_off`; from then on `pending_stop` owns the obligation (R1-06, R2-02).

### C4. Watcher classification order (fan_manual_watch.yaml), evaluated on every fan state event with `event_ts = trigger.to_state.last_updated`

| # | Verdict | Condition (first match wins) |
|---|---|---|
| 1 | replay | `trigger.to_state` is none, or `trigger.from_state` is none, or `from_state.attributes.restored` is true |
| 2 | recovery | from-state or to-state in `unavailable`/`unknown` |
| 3 | no-op | state, percentage and direction all unchanged (other attributes only) |
| 4a | overwritten → ignore (R1-12) | a valid stamp exists with `stamp_ts > event_ts` (the slot was re-stamped after this event; the writer's next step live-checks the fan itself) |
| 4 | own write | a valid stamp exists, `stamp_ts <= event_ts <= stamp_ts + lag_seconds`, to-state equals `stamp_state`, percentage equals `stamp_pct` when asserted, and — only when the event changed the direction attribute (`from_state.attributes.direction != to_state.attributes.direction`) — direction equals `stamp_dir` when asserted (R1-01) |
| 5 | cutoff / resume (kids instance only) | off-branch: on→off while the cutoff automation's `current` ≥ 1 and the cutoff sensor is `on` or changed state within lag before `event_ts`. resume-branch (R1-15): off→on with the cutoff automation ended (`current` 0 and its `last_updated` within lag before `event_ts`) and the sensor `off` for ≥ hold − 15 s at `event_ts`. Any off→on while `current` ≥ 1 is the cancel path = manual (residual vii: a resume whose state event precedes the run's end reads manual — safe direction). |
| 6 | manual | everything else → `input_datetime.set_datetime` on the since helper with `timestamp: event_ts` |

An invalid stamp (C2) is "no stamp" for M (everything unstamped is manual — the safe direction). The former seasonal rule is gone: S v2.0 stamps, so its writes match rule 4; an older unstamped S would read manual. The watcher never writes a stamp, never calls a `fan.*` service, and notifies only when its since helper is missing (`fan_manual_watch_<fan>_helper_missing`).

### C6. Daytime blueprint (bedroom_fan_daytime.yaml) behavioural contract

Windows: `day_start` 08:00, `day_end` 18:00, `day_end_margin` 5 → `wrap_ts` = 17:55. New transactions for normal writes (vacancy-off, nap band, direction phase, reversal) only in `[day_start, wrap_ts)`; wrap-up transactions (nap-end off and direction restore of a nap N itself ended) until `wrap_end` = `day_end` + `wrap_grace_minutes` (30 → 18:30; Martin 2026-09-24), each still interlock-gated and stamped; no new transaction at or after `wrap_end` until `day_start`. Pending-stop re-issues and cuts follow C3 regardless of window, so the last possible N fan call is `wrap_end` + `stop_deadline_seconds` = 18:34. No reversal may start within 10 min of `wrap_ts` (17:45). The nap-toggle lifecycle (start, end, 3 h cap, stale reset) runs 24 h; only fan transactions are day-gated.

Vacancy: `activity_ts` = max of every activity sensor's `last_changed` (either state), `since_ts`, and `nap_on_ts` while the toggle is on. `vacancy_due` = in day window, fan available and on, record ok and valid, `now_ts - activity_ts >= vacancy_minutes·60`, not blocked, not `already_written`, not `foreign_fresh`, no `pending_stop` of mine open, and not exempt. Exempt = `stamp_writer == precool and stamp_ts >= day_start_ts` (fan-assist, example 26), or the nap fan while `nap_active` and `ours`. Master instance: activity = stairs PIR only (hand-started fan limitation, example 3).

Nap (kids instance; empty `nap_toggle` disables everything below; `nap_since_helper` required when `nap_toggle` is set): start when the Off button (`nap_start_button`) reports `short_release` while the gate entity is `on`, inside the day window, toggle off, temperature valid → `input_datetime.set_datetime` on `nap_since_helper` (now) then `input_boolean.turn_on`. On every genuine off→on toggle event (restored guard) N also writes `nap_since` = `trigger.to_state.last_changed` unless the helper already holds an instant within 60 s of it (covers the dashboard fallback and is restart-stable, R1-05). Reference `nap_on_ts` = the `nap_since` helper's timestamp, never the toggle's `last_changed`; a toggle that is on with `nap_on_ts < day_start_ts` on a day tick is stale → switched off before any fan logic. End on: any `nap_end_buttons` entity `short_release` while the gate is `off`; the gate turning `on`; cap (`now_ts - nap_on_ts >= nap_max_hours·3600`, any hour); forced end at `wrap_ts`; the toggle switched off by hand. Nap end = toggle off first (the nightlight follows within a minute), then for `nap_end_retry_minutes` after the toggle went off (a forced end at `wrap_ts` retries until `wrap_end`): if the fan is `ours` and on and not blocked → open a stop transaction (stamp `daytime|off|*|*` + `turn_off`; `pending_stop` then owns it); once the fan reads off with my plain off stamp, `fan.last_changed - stamp_ts <= lag_seconds` (it was my off that landed), `direction_mode != cooling_only`, live direction ≠ rest direction and `not manual_veto(stamp_txn)` → direction phase `daytime|off|*|<rest>|now|stamp_txn` + `set_direction` (R2-04 veto applies here and in the 18:00–18:30 wrap-up). Still ours-on after the retry window → one notice `nap_end_failed`.

Band: `need_cool_start` = temp ≥ ideal + tolerance (24.5); `need_warm_start` = temp ≤ ideal − tolerance (21.5); `cool_hold` = temp > ideal + tolerance − hysteresis (23.5); `warm_hold` = temp < ideal − tolerance + hysteresis (22.5). Regime from the live fan while `ours`: on + cooling direction = cooling; on + warming direction = warming; else idle. `desired` = cool if (cooling and cool_hold) or (not cooling and need_cool_start); warm if direction_mode ≠ cooling_only and ((warming and warm_hold) or (not warming and need_warm_start)); else off. Temperature `unavailable`/`unknown`/non-numeric: no nap start; an ours fan running → stop transaction + notice `sensor`; temp < `floor_temp` (16) → desired off + overcooling notice. Band-off = a stop transaction on an ours fan. **Start from off** (`start_due`): `nap_active`, desired ≠ off, fan off and available, record ok and valid, not blocked, not `already_written`, not `foreign_fresh`, `since_ts < nap_on_ts`, not `owned_by_other(nap_on_ts)`, no aborted direction stamp of this nap (C3), and the first-start rule: either a plain stamp of mine with `stamp_ts >= nap_on_ts` exists (a restart after a band-off or reversal stop — allowed any time), or `now_ts - nap_on_ts <= blocked_notice_minutes·60`, or no interlock sensor has changed state since `nap_on_ts` (never blocked this nap; a temperature-driven first start is allowed at any hour of the nap, R1-11). A first start that has been interlock-blocked for the whole 10 min → one notice `blocked` and, because a sensor changed after `nap_on_ts`, no first start for the rest of that nap (example 10). Then: live direction equals the needed direction → stamp `daytime|on|<pct>|<dir>|now|now` + `turn_on`; else in `cooling_only` → notice `direction_mode` (D4), nothing; else → direction phase `daytime|off|*|<needed>|now|now` + `set_direction`. **Direction-phase continuation:** my `off` stamp with dir asserted, fan off, live direction == `stamp_dir`, `now_ts - stamp_ts <= direction_wait_seconds`, desired still wants `stamp_dir`, not blocked, `not manual_veto(stamp_txn)`, slot still mine → stamp `daytime|on|<pct>|<dir>|now|stamp_txn` + `turn_on`; timeout → abort (C3). A fan on but not ours (manual, pre-cool) is the parent's or pre-cool's for that nap: no band writes, no nap-end off (example 37); vacancy-off still applies to a manual fan.

Direction: cooling direction = `summer_direction` (forward), warming = `winter_direction` (reverse), rest direction = winter if `season_toggle` is on else summer, read live at use. `direction_mode`: `cooling_only` — never writes direction; starts only when the live direction already equals the cooling direction (a fan resting in the warming direction gets one state-driven notice and no nap fan); `both_at_start` — sets direction only while the fan is off (start from off, nap-end restore), never stops a running fan for direction; `both_with_reversal` — additionally the **reversal**: fan ours-on with live direction ≠ needed, `now_ts - as_timestamp(fan.last_updated) >= reversal_dwell·60`, before 17:45, not blocked → a plain stop transaction (`daytime|off|*|*|now|now` + `turn_off`); once it reads off, the start-from-off rule (restart branch) performs the direction phase and the restart. At most one reversal per dwell by construction (our own off and restart move `last_updated`). Abort of the direction phase or a `stop_fault` ends the reversal: fan left off (direction phase) or running in the old direction under the cutoff/manual regime (stop fault), one notice, no retry that nap.

Cut (kids): `cut_due` per C3 with W = daytime, then `pending_stop`.

Notifications (fixed ids `bedroom_fan_daytime_<condition>_<this.entity_id with '.' → '_'>`): `blocked`, `reversal_aborted`, `stop_failed`, `nap_end_failed`, `sensor` (invalid or < floor), `fan_unavailable` (nap start only), `record_missing`, `record_invalid`, `direction_mode`. Each is created while its condition holds and dismissed at the next nap boundary or day boundary, or when the fan reads off for `stop_failed`.

### C7. Pre-cool v1.3.0 contract (bedroom_precool.yaml)
