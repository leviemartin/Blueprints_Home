### C2. Daytime blueprint contract (bedroom_fan_daytime.yaml)

**Inputs** (`fan` required; everything else has a default so the deploy dry-run passes with `fan` alone): `fan`; `activity_sensors` (binary_sensor, multiple, default `[]`); `day_start` 08:00:00; `day_end` 18:00:00; `day_end_margin_minutes` 5; `vacancy_minutes` 20; `nap_toggle` (input_boolean, default `[]`); `nap_since_helper` (input_datetime, default `[]`); `nap_start_button` (event, default `[]`); `nap_end_buttons` (event, multiple, default `[]`); `gate_entity` (light, default `[]`); `nap_max_hours` 3; `enable_notifications` true. Every input is passed through top-level `variables:` as `<name>: !input <name>`.

**Triggers** (each with an id): `time_pattern` minutes `/1` (`tick`); `homeassistant` start (`ha_start`); state on `nap_toggle` (`nap_toggle`, no to/from); state on `nap_start_button` (`nap_start`); state on each `nap_end_buttons` entity (`nap_end`); state on `gate_entity` `to: on` (`gate_on`). **Global condition** (restored-trigger guard): `trigger.id is not defined or trigger.id in ['tick', 'ha_start'] or (trigger.from_state is not none and not (trigger.from_state.attributes.restored | default(false)))`. `mode: queued`, `max: 10`, `max_exceeded: silent`. A manual "Run" (no `trigger.id`) and the `ha_start` run evaluate everything and actuate nothing (`is_real_trigger` = `trigger.id is defined and trigger.id != 'ha_start'`; brief §7 "ha_start re-evaluates only" — consistency-check item 5).

**Predicates** (one action-level `variables:` step, instants as unix timestamps; tests render these names):
- `now_ts`; `day_start_ts = as_timestamp(today_at(day_start))`; `day_end_ts` likewise; `wrap_ts = day_end_ts - day_end_margin_minutes*60`; `in_day = day_start_ts <= now_ts < day_end_ts`.
- `fan_avail = states(fan) not in ['unavailable', 'unknown']`; `fan_on = is_state(fan, 'on')`; `fan_touch_ts = as_timestamp(fan.last_updated)` (a state or attribute change, a flap or any writer's landed command all count — a flap only delays an off).
- `occupied_now` = any configured sensor reads `on`. `sensor_ts` = the latest `last_changed` over the configured sensors (a sensor reading `off` contributes its last clear, Martin's rule; a sensor reading `unavailable`/`unknown` contributes the instant it dropped; a sensor absent from the state machine contributes 0).
- `has_nap` = `nap_toggle` and `nap_since_helper` both configured and both present in the state machine and not `unavailable`. `nap_on = has_nap and is_state(nap_toggle, 'on')`; `since_ts` = the since helper's timestamp (0 when unset); `toggle_ts` = the toggle's `last_changed` (0 without `has_nap`); `gate_on` = gate configured and `on`.
- `activity_ts = max(sensor_ts, fan_touch_ts, toggle_ts)`; `vacant = not occupied_now and now_ts - activity_ts >= vacancy_minutes*60`.
- `nap_stale = nap_on and now_ts >= day_start_ts and since_ts < day_start_ts`; `nap_cap = nap_on and now_ts - since_ts >= nap_max_hours*3600`; `nap_forced = nap_on and in_day and now_ts >= wrap_ts`.
- `gesture = trigger.to_state.attributes.event_type | default('')` (button triggers). `nap_start_due = has_nap and not nap_on and trigger.id == 'nap_start' and gesture == 'short_release' and gate_on and day_start_ts <= now_ts < wrap_ts`. `nap_end_due = nap_on and ((trigger.id == 'nap_end' and gesture == 'short_release' and not gate_on) or trigger.id == 'gate_on' or nap_cap or nap_forced or nap_stale)`. `since_fallback_due = has_nap and trigger.id == 'nap_toggle' and to_state on and from_state off and |since_ts - as_timestamp(trigger.to_state.last_changed)| > 60` (a dashboard flip; N's own start wrote the since first, so no rewrite).
- `exempt = (nap_on and not nap_stale) or nap_start_due`. `off_due = is_real_trigger and in_day and fan_avail and fan_on and vacant and not exempt`.
- `config_error` = exactly one of `nap_toggle`/`nap_since_helper` configured, or a configured helper missing/`unavailable`, or `activity_sensors` empty. A configuration error never suppresses an off; it disables the nap lifecycle (`has_nap` false) and raises one notice.

**Actions, in this order:** (1) the variables step; (2) nap start: `input_datetime.set_datetime` on the since helper with `timestamp: now_ts`, then `input_boolean.turn_on`; (3) since fallback: `set_datetime` with `trigger.to_state.last_changed`; (4) nap end: `input_boolean.turn_off`; (5) vacancy-off: one `choose` whose branch condition repeats the rule on live state (`off_due and is_state(fan, 'on') and no activity sensor reads on`) and issues exactly one `fan.turn_off` (target the `fan` input, `continue_on_error: true`); (6) the config notice (`persistent_notification.create` while `config_error and enable_notifications`, `dismiss` otherwise; fixed id `bedroom_fan_daytime_config_{{ this.entity_id | replace('.', '_') }}`). No `wait_template`, `delay`, `wait_for_trigger` or `repeat`. Allowed services: `fan.turn_off`, `input_boolean.turn_on`, `input_boolean.turn_off`, `input_datetime.set_datetime`, `persistent_notification.create`, `persistent_notification.dismiss` — nothing else (no `homeassistant.*`, `script.*`, `automation.*`, `fan.turn_on`, `fan.set_direction`, `fan.set_percentage`, `fan.toggle`). The off is never gated on the cutoff's sensor: an off cannot cancel the cutoff's resume (only an on does), and the PIR's clear is activity, so the fan runs at least `vacancy_minutes` after any cutoff event before N acts (amendment carry-over, matrix row C–N).

**Instances** (`deploy/bedroom_fan_daytime_kids.json`, `deploy/bedroom_fan_daytime_master.json`; `trace.stored_traces` 60): kids — id `bedroom_fan_daytime_kids`, alias "Kids room — fan daytime v1.0.0", fan fan.ceiling_fan_light_v2, activity [binary_sensor.stairs_motion, binary_sensor.samuel_samuel_matthew_fanprotection], nap_toggle input_boolean.kids_nap, nap_since_helper input_datetime.kids_nap_since, nap_start_button event.baby_room_button_4, nap_end_buttons [event.baby_room_button_2, event.baby_room_button_3], gate light.kids_room_gate; master — id `bedroom_fan_daytime_master`, alias "Master bedroom — fan daytime v1.0.0", fan fan.ceiling_fan_light_v2_2, activity [binary_sensor.stairs_motion], no nap inputs. 2. `mode: queued`, `max: 10`, `max_exceeded: silent`; a 1-minute tick plus event triggers; no fan or sensor state triggers (the tick evaluates them).
3. An `unavailable` sensor counts as no activity since it dropped (fails toward off). A fan reading `unavailable`/`unknown` gets no command.

5.
