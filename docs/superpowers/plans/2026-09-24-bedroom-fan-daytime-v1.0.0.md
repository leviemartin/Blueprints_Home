## Roles (one sentence each; every contract below follows from these)

- **Dispatcher D** (`fan_dispatch.yaml`, script blueprint, one instance per fan: `script.kids_fan_dispatch`, `script.master_fan_dispatch`): the only fan writer; each run is one atomic step with no in-run wait; derives obligations from the record and live state on every run before it looks at the request.
- **Clock K** (`fan_dispatch_clock.yaml`, automation blueprint, one per fan): calls the dispatcher's `reconcile` on a 1-min tick (only while a transaction is open or an interlock reads on), on every fan or interlock state event (immediately and again 12 s later), and at HA start; never disabled as an escape hatch.
- **Watcher M** (`fan_manual_watch.yaml`, one per fan): classifies fan state events against the journal and writes since only for genuine manual changes; never writes the record, the journal or the fan.
- **Requesters** N (daytime, new), P (pre-cool v1.3.0), S (seasonal v2.0): compute their own due rules from the record, since and live state and ask the dispatcher via `script.turn_on` with a request; they never call a `fan.*` service and never write the record or journal.
- **Cutoff C** and **dimmer** (unchanged): command the kids fan outside the dispatcher; M attributes C's off/resume (rule 5) and the dimmer's presses (manual).

The `input_text` helpers are created **without `initial`** and set to empty once by stage 8 step 1 (an `initial` value would reset the record and journal at every HA start; without it the last value is restored — R2-03). Instants are read as `state_attr(<input_datetime>, 'timestamp')`, never `as_timestamp(states(...))`. **Record health (`record_ok`)** for a consumer: every helper it is configured with exists in the state machine and is not `unavailable`; an empty or `unknown` record or journal is a valid "no record"; the consumer's `watcher_automation` exists and is not `unavailable` (its on/off state is a separate gate, C3). For requesters `record_ok` also requires the configured dispatcher script entity to exist and not be `unavailable`. A consumer whose record is not ok issues nothing (requesters: no request; D: no command) and raises one fixed-id notice (`…_record_missing`, naming the helper or entity). **Record validity (`record_valid`)**: the strict checks of C2; an invalid record fails closed exactly like a missing one, with its own notice (`…_record_invalid`) whose text gives the recovery (set the record helper to empty; set a future since to a past instant); the helpers stay off dashboards.

### C2. Record, journal, since — formats and strict validation

**Record** (`input_text.<fan>_expected`, written only by D, exactly 10 `|`-separated fields):

```text
v1|<owner>|<state>|<pct>|<dir>|<ts>|<txn>|<goal>|<lifecycle>|<latch>
owner ∈ {precool, daytime, seasonal}; state ∈ {on, off}; pct = 0..100 or *; dir ∈ {forward, reverse, *}
ts = unix seconds (int) of the latest command issue; txn = unix seconds of the first command of this transaction (txn <= ts)
goal ∈ {none, stop, cut, dir:<d>, start:<d>:<p>, reverse:<d>:<p>}   (d ∈ {forward, reverse}, p = 1..100)
lifecycle = unix seconds (int): the requester's lifecycle instant this transaction belongs to (C4)
latch ∈ {none, stop_failed:<ts>, aborted:<ts>}
example: v1|daytime|off|*|*|1790000600|1790000600|reverse:reverse:1|1790000000|none  (a reversal in its stop phase)
```

Validation: exactly 10 fields, field 1 `v1`, enumerations as above, pct/p digits in range, ts/txn/lifecycle/latch-ts all digits with `txn <= ts` and `ts <= now_ts + skew` where `skew` = 5 s (the record is written by an earlier serialized run on the same host clock, so a future ts can only be corruption; the 5 s bound covers a value written while a concurrent run's `now_ts` was already computed — no 60 s allowance, R2-08). Empty or `unknown` = "no record" (valid). Anything else = invalid (fail closed, C1).

**Journal** (`input_text.<fan>_journal`, written only by D, immediately before every fan command): entries `<state>|<pct>|<dir>|<ts>` joined by `;`, newest first, at most 8 entries (D drops the oldest). Each entry is validated like the matching record fields; an entry that fails validation is ignored by M (and, when any entry is invalid, D raises `record_invalid` and issues nothing). The journal is M's only stamp source: the **stamp in force at `event_ts`** is the newest entry with `ts <= event_ts`.

**Since** (`input_datetime.<fan>_manual_since`): `since_ts` = its `timestamp` attribute; valid when the attribute is present, numeric, finite and `<= now_ts + skew`; an unset helper (`unknown` state or missing attribute) is **"unset"**, distinct from 0: consumers treat "unset" as "no manual change ever" only when the helper exists and is not `unavailable` (R2-08); a future since is invalid (fail closed), never "manual" and never "untouched".

### C3. Dispatcher contract (fan_dispatch.yaml)

**Inputs:** `fan` (required); `record_helper`, `journal_helper`, `since_helper`, `watcher_automation` (required); `interlock_sensors` (binary_sensor, multiple, default `[]`), `interlock_clear_minutes` 5, `lag_seconds` 120, `stop_deadline_seconds` 240 (= 2 × lag), `direction_wait_seconds` 90, `attribution_grace_seconds` 10, `request_max_age_seconds` 90, `max_runs` 30, `enable_notifications` true. **Fields (the request):** `requester` ∈ {precool, daytime, seasonal, clock}; `intent` ∈ {reconcile, on, off, set_direction, reverse}; `pct` (int, `on` only; `reverse` snapshots the live pct); `direction` (forward/reverse; `on` optional, `set_direction`/`reverse` required); `lifecycle_ts` (int, required except `reconcile`); `request_ts` (int, required); `reason` (short text, trace only). `mode: queued`, `max: 30`, `max_exceeded: warning`, `trace: stored_traces: 40`. **No `wait_template`, `delay`, `wait_for_trigger` or `repeat` anywhere** (structure test); one run = one pass over the sequence below, at most one `fan.*` call.

**Run sequence (variables first, then one `choose`):**

1. **Read** `now_ts`; parse the record (`rec_*`) and since; `record_ok`, `record_valid` (C1/C2); live fan `fan_state` (`on`/`off`/`unavailable`/`unknown`), `fan_pct`, `fan_dir`, `fan_last_changed_ts`, `fan_last_updated_ts`; interlock rule `blocked` = any configured sensor `on`/`unavailable`/`unknown`/absent or changed within `interlock_clear_minutes`; `sensor_on` = any sensor reads `on`, `sensor_on_ts` = the latest `last_changed` among sensors reading `on`; `watcher_on` = the watcher automation's state is `on`; `quiet` = `now_ts - fan_last_updated_ts >= attribution_grace_seconds`; `req_ok` = fields well-formed and `now_ts - request_ts <= request_max_age_seconds` (a stale request is dropped: state may have changed while it was queued; the requester re-requests on its tick); `obligation_open` = `rec_state == 'off'` and `rec_goal in (stop, cut)` or (`rec_goal` is `reverse:*` and `rec_dir == '*'`) and `fan_state == 'on'`; `manual_veto_txn` = since valid and `since_ts >= rec_txn`; `latched_for(ts)` = `rec_latch != none and ts <= latch_ts`.
2. **Record gate:** not `record_ok` or not `record_valid` → notice, **no command**, end (fail closed; the cutoff is the backstop; documented residual A10).
3. **Obligation A — cut** (evaluated first on every run, never quiet-guarded, allowed while blocked): `sensor_on and rec_state == 'on' and now_ts - rec_ts <= lag_seconds and fan_state in (on, off)` (our on is in flight or just landed under a tripped sensor) → `decision = cut`: journal + record `v1|<owner>|off|*|*|now|now|cut|<sensor_on_ts>|<latch>` → `fan.turn_off`. A cut with `rec_goal` already `cut` and `fan_state == on` falls to B.
4. **Obligation B — pending stop:** `obligation_open` → (i) `manual_veto_txn` → `decision = abandon` (the person owns the fan: record goal `none`, owner unchanged, no command); (ii) else `now_ts - rec_txn >= stop_deadline_seconds` → `decision = fault`: record `latch = stop_failed:<now>`, goal `none`, notice `stop_failed`, no command, no further re-issue; (iii) else `now_ts - rec_ts >= lag_seconds and quiet and fan_state == on` → `decision = reissue_off`: journal + record (ts = now, same txn, same goal) → `fan.turn_off` (allowed while blocked); (iv) else `decision = wait`. A fan reading `unavailable` yields `wait` (the obligation persists; the deadline does not move). The predicate never consults `fan.last_changed`: a recovery or restart cannot end an obligation; only the fan reading off, a manual verdict since `txn`, or the deadline does (R2-03).
5. **Obligation C — goal continuation** (fan reads off, `rec_state == off`, goal is `dir:`, `start:` or `reverse:`): any `sensor_on` while the goal is open with the fan off → `decision = abort` (record `latch = aborted:<now>`, goal `none`, notice `reversal_aborted`, fan left off; wave-1 example 8). Else: (a) direction phase due (`rec_dir == '*'`, goal carries `<d>`): gates `not blocked and watcher_on and not manual_veto_txn and quiet` → if `fan_dir != d`: journal + record `off|*|<d>|now|txn` → `fan.set_direction`; if `fan_dir == d`: record `off|*|<d>` (no command, no journal) and continue to (c) in the same run; (b) direction wait (`rec_dir != '*'`): `fan_dir == rec_dir` → (c); else `now_ts - rec_ts > direction_wait_seconds` → `abort` (issued once, never re-issued, R2-11); else `wait`; (c) restart phase (goal `start:`/`reverse:` with `<p>`): gates `fan_state == off and fan_dir == d and not blocked and watcher_on and not manual_veto_txn and quiet and not latched_for(rec_lifecycle)` → journal + record `on|<p>|<d>|now|txn` → `fan.turn_on percentage p`. Goal `dir:` completes when `fan_dir == d`.
6. **Request handling** (only when steps 3–5 produced no command and `req_ok`; `reconcile` ends here). Precedence: obligations > `off` > `reverse` > `set_direction` > `on`.
   - `off`: fan off and no in-flight on → `refuse:already_off` (if `rec_goal` is open, set goal `stop`, no command). Fan on, or our on in flight (`rec_state == on and now_ts - rec_ts <= lag`) → gates: `quiet`; `not latched_for(lifecycle_ts)` for a `stop_failed` latch (R2-07: the same lifecycle cannot reopen the failed stop) → journal + record `v1|<requester>|off|*|*|now|now|stop|<lifecycle_ts>|<latch>` → `fan.turn_off` (allowed while blocked; allowed with the watcher off). Any requester may stop any fan; the owner becomes the requester.
   - `reverse` (fan on): gates `not obligation_open and not blocked and watcher_on and quiet and since_ts < lifecycle_ts and not latched_for(lifecycle_ts)`; owner = the record's owner when `rec_state == fan_state` and (pct unasserted or equal) — ownership-preserving, R2-05 — else the requester; `p` = the request's `pct` if given else the live pct (≥ 1) → journal + record `v1|<owner>|off|*|*|now|now|reverse:<d>:<p>|<lifecycle_ts>|<latch>` → `fan.turn_off`. Fan off → treated as `set_direction`.
   - `set_direction` (fan off): gates `not obligation_open and not blocked and watcher_on and quiet and since_ts < lifecycle_ts and not latched_for(lifecycle_ts)` → if `fan_dir == d` → `refuse:already` else journal + record `v1|<owner or requester>|off|*|<d>|now|now|dir:<d>|<lifecycle_ts>|<latch>` → `fan.set_direction`. Owner preserved as for `reverse`.
   - `on` (fan off): gates `not obligation_open and not blocked and watcher_on and quiet and since_ts < lifecycle_ts and not latched_for(lifecycle_ts)` and **foreign in-flight veto**: `rec_owner != requester and now_ts - rec_ts <= lag_seconds` → `refuse:foreign_fresh`; and **owned-running veto** (applies to `on` on a fan that reads on): `refuse:owned` — the dispatcher never re-speeds a running fan owned and matched by another requester (example 27; P assist never touches an N-owned nap fan). With `direction` given and `fan_dir != d` → goal `start:<d>:<p>` and the direction phase first (record `off|*|<d>` → `fan.set_direction`); else journal + record `v1|<requester>|on|<p>|<fan_dir or d>|now|now|none|<lifecycle_ts>|<latch>` → `fan.turn_on percentage p`. A plain on is not an obligation: if it never lands the requester re-requests after `lag_seconds` (`already_written`, C4); a run that finds its own `on` in flight → `refuse:already_written`.
   - Every energize refusal (`blocked`, `watcher_off`, `vetoed`, `latched`, `foreign_fresh`, `owned`, `obligation_open`, `not_quiet`, `stale`) is a trace variable; D raises notices only for `stop_failed`, `reversal_aborted`, `record_missing`, `record_invalid`, `watcher_off` (state-driven, fixed ids `fan_dispatch_<condition>_<fan entity with '.' → '_'>`; `stop_failed` dismissed when the fan reads off; the others when their condition clears).
7. **Completion:** when `rec_state == fan_state`, (pct unasserted or equal), and the goal is reached (`none`/`stop`/`cut` with the fan off; `dir:` with the direction matched; `start:`/`reverse:` with the fan on at `<p>` in `<d>`) → record `goal = none` (write only if it changes; ts, txn, owner, latch unchanged; no journal entry). A `stop_failed` latch is cleared only by a transaction with `lifecycle > latch_ts` that completes, or by Martin emptying the record; an `aborted` latch likewise.

**Write invariant ("no stamp, no command"):** immediately before every `fan.*` call D (1) writes the journal, (2) writes the record, both with `input_text.set_value` carrying neither `continue_on_error` nor `enabled: false` (a rejected write ends the run before the command), (3) reads the record back and proceeds only if it holds exactly the string just written, (4) calls the fan with `continue_on_error: true` (`percentage` on every `turn_on`, never `fan.set_percentage`, never `percentage: 0`). Live re-checks in the command step repeat the gates on live state.

**Arbitration summary (the priority order Martin asked for):** derived obligations first (cut, then pending stop, then goal continuation); then requests in the order `off` > `reverse` > `set_direction` > `on`; an energize request while any obligation is open is refused; an `off` is never refused for ownership; a `stop_failed` latch blocks every automatic transaction of the same or an older lifecycle (a new nap, a new day, a new night, a new toggle flip or a new interlock on-transition is a new lifecycle); the watcher's health gates energize only; the interlock rule gates everything except offs.

### C4. Requester contract (N, P, S)

Requesters call the dispatcher **only** with `action: script.turn_on`, `target: entity_id: <dispatcher>`, `data: variables: {requester, intent, pct, direction, lifecycle_ts, request_ts, reason}` (non-blocking: the call returns once the run is queued; a direct `script.<id>` call would block the requester until its queued run finished and would cancel that run if the requester's own run were cancelled — P runs `mode: restart` — so the direct form is banned by structure test in N, P, S and K). Requesters compute, from the record (C2), since and live state:

- `since_ts` per C2 ("unset" = no manual change; invalid = fail closed).
- `rec_owner`, `rec_state`, `rec_pct`, `rec_dir`, `rec_ts`, `rec_txn`, `rec_goal`, `rec_lifecycle`, `rec_latch` or "no record".
- `stamp_matches`: live state equals `rec_state` and live pct equals `rec_pct` when asserted (direction is not part of ownership).
- `ours` (per requester W): `record_ok and record_valid and rec_owner == W and stamp_matches and (since unset or since_ts < rec_txn)`.
- `owned_by_other(ref_ts)`: `rec_owner != W and rec_ts >= ref_ts` (and, for a running fan, `stamp_matches`).
- `already_written`: `rec_owner == W and now_ts - rec_ts <= lag_seconds` (do not re-request for one lag).
- `manual_in_window(start_ts)`: `since_ts >= start_ts`.
- `latched`: `rec_latch != none and rec_latch_ts >= <my lifecycle_ts>` (do not request; the dispatcher would refuse).
- `lifecycle_ts` sent with every request: N nap requests → `nap_on_ts`; N vacancy-off → `day_start_ts`; P night → `window_start_ts`; P assist → `ac_started_ts`; P `fans_on_at_wake` → `lock_ts`; S → the toggle's `last_changed` of the genuine flip.

Requesters request only while their due condition holds and the record does not already reflect the request (no request storm; the dispatcher dedupes anyway). Requesters never evaluate interlocks as a permission to command (the dispatcher does) but N and P keep the interlock rule in their *notices* (`blocked`) and P keeps its v1.2.1 rule for fans without a record. Requesters never call `fan.*` (grep gate) and never write the record or journal.

### C5. Watcher classification order (fan_manual_watch.yaml), evaluated per fan state event with `event_ts = trigger.to_state.last_updated`

| # | Verdict | Condition (first match wins) |
|---|---|---|
| 1 | replay | `to_state` none, `from_state` none, or `from_state.attributes.restored` true |
| 2 | recovery | from-state or to-state in `unavailable`/`unknown` |
| 3 | no-op | state, percentage and direction all unchanged |
| 4 | own write | the journal's stamp in force at `event_ts` (C2) has `event_ts <= ts + lag_seconds`, to-state equals its state, percentage equals its pct when asserted, and — only when the event changed the direction attribute — direction equals its dir when asserted (R1-01). A newer journal entry with `ts > event_ts` is ignored for this event (R2-06 replaces wave-1 rule 4a) |
| 5 | cutoff / resume (kids instance only) | off-branch: on→off while the cutoff automation's `current` ≥ 1 and the cutoff sensor is `on` or changed within lag before `event_ts`. resume-branch: off→on with the cutoff run ended (`current` 0, its `last_updated` within lag before `event_ts`) and the sensor `off` for ≥ hold − 15 s at `event_ts`. Any off→on while `current` ≥ 1 is the cancel path = manual (residual vii) |
| 6 | manual | everything else → `input_datetime.set_datetime` on the since helper with `timestamp: event_ts` |

## The queued-script blocking hazard — answer and its interleaving test

Hazard: a `mode: queued` script that waits in-run blocks every later call — including a cut — for the wait's duration. **Answer:** the dispatcher never waits in-run: no `wait_template`, `delay`, `wait_for_trigger` or `repeat` (structure test), so each run is bounded by a handful of template evaluations, at most two `input_text.set_value` calls, one read-back and one `fan.*` service call; multi-phase work (verified stop → direction → restart) is carried by the record's goal and resumed by the clock's state- and tick-driven `reconcile` calls, never by waiting. Requesters use the non-blocking `script.turn_on` form, so no requester run is held on the queue and no cancelled requester can cancel a dispatcher run. Cuts and pending stops are derived from the record and live state at the top of every run, so whatever the request that dequeues next, the first fan command of that run is the safety one. The only residual latency is the queue depth times one run (bounded by the Tuya service call's own return time; stage 8 step i verifies runs complete in < 5 s and `current` never exceeds 2 during the live probes). HA facts relied on (as this plan's author knows the script integration; stage 8 step i re-verifies live): a queued script executes runs strictly one after another in call order; `max` bounds running plus queued runs, beyond which the call is dropped with a log at `max_exceeded` level; `script.turn_on` with `data.variables` returns without waiting for the run; a direct `script.<id>` call passes its data as variables and blocks until that run completes; `fields` document the request and are ordinary variables in the sequence; an `input_text` created without `initial` restores its last value at start.

**Interleaving test** `test_cut_is_never_delayed_behind_a_phase`: queue in order — (1) S `reverse` on a running N-owned fan → `turn_off`, record goal `reverse:reverse:1`; (2) reconcile with the fan reading off at t+40 → `set_direction`; (3) the kids PIR reads on at t+50 with the fan still off → the next run, whatever its request (a queued P `on` at t+52), evaluates C3 step 5 first → `abort` (no `turn_on`); (4) variant: the restart landed at t+100, the sensor trips at t+110, a queued S `reverse` request at t+111 → the run's step 3 issues `cut` and the S request is not evaluated (one command per run); (5) variant: a run holding a `wait` decision never delays anything (the step's rendered decision is `wait`, and the structure test proves no waiting construct exists). Each step asserts the decision and that no step's rendered sequence contains more than one `fan.*` call.
