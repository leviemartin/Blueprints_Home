## 0. Premise verdict

- **Should this exist?** Yes.
- **Reasoning:** The v1.1.1 rack instance heats a 21–23 °C September bathroom 4–5 h/day, starts evening heat on the first staircase movement up to 90 min early, and has logged 3,336 `Service not found` errors since 09-04 (the warmup notification fires every active-window minute because the Tuya device always reports `preset_mode: eco`, and the push target does not exist). The spec (design board 20260907-134749 PASS) and Martin's locked decisions fix exactly those; the research validation (verdict `proceed`) names the rack retune as part of the approved approach.
- **Alternatives considered:** (a) data-only retune of the v1 instance (`enable_predictive_motion: false`, Fold target, new slots) — removes the early starts and the missing service, but leaves the per-tick notification (the `preset == 'eco'` condition is always true on this device), the no-floor heating of an already-warm room, and the bare-`false` vacation branch; rejected. (b) v2 as specified — chosen. (c) hysteresis as a new input — rejected (no new knob; a fixed 0.5 °C deadband is below every selector step and above the sensor noise).
- **Pass 0 (research re-check):** `~/AI/docs/research/2026-09-07-bathroom-ventilator-v2-research-validation.md` present (2026-09-07, verdict `proceed`). Anti-patterns 1–5 concern the ventilator; **anti-pattern 6 ("re-notifying on every qualifying tick instead of edge-triggered once-per-transition")** applies to the rack and is honoured by the plan's edge conditions — and it is the basis for finding P1-1 below (sensor-noise transitions are still "every qualifying tick" in disguise).

## 1. Findings

### P0 — must address before execution
None found, having looked for: data loss (none — instance backup to `deploy/1776551429917.prev.json`, blueprint in git), an instance left `unavailable` (dry-run key validation + `validate_config` + the post-deploy `on` assert), a runaway heater (idle = `heat_cool` @ 7 °C proven live since v1.0.5; vacation = `off`; every setpoint path bounded by the selector max 28 / boost max 28), secrets in the artifacts (entity ids only), and a wrong push target (instance JSON pins `notify.mobile_app_martin_fold`, which exists).

### P1 — significant gap
1. **Comfort-floor flip → repeated warmup pushes (actioned).** Plan T2 `ea_active: "{{ ea_in_window and indoor_temp | float < evening_a_target_temp | float - comfort_floor_delta | float }}"` (first draft) combined with the edge condition `current_setpoint ≤ idle_setpoint + 0.1` makes every sensor-noise crossing of the floor line an idle→target transition, i.e. a `climate.set_temperature` call plus a "Warmup started" push. Live history 2026-09-07 13:14–13:39 (`22.3 → 21.9 → 21.6 → 22.0 → 22.3 → 22.2`) against the morning floor 23 − 1.0 = 22.0 is three rises in 25 minutes. Source: research anti-pattern 6; Hue temperature cadence probed live. **Fix applied:** `floor_hysteresis = 0.5 if current_setpoint > idle_setpoint + 0.1 else 0`, per-slot `<p>_floor = (target − delta + floor_hysteresis) | round(2)`, `<p>_active = in_window and indoor | round(2) < floor`; spec §4.1 row updated (commit `a25108a`); tests `test_comfort_floor_hysteresis_rows`, `test_comfort_floor_non_dyadic_rows`.

### P2 — clear bug or omission
1. **Grid rounding on non-dyadic values (actioned).** `(((raw / step) + 0.5) | int) * step` lands one step low when `raw/step` carries binary dust (memory `feedback_jinja_grid_quantization_raw_float_compares`, LG AC v1.2.0). **Fix applied:** `((((raw / step) + 0.501) | int) * step) | round(2)`; gate compares carry `round(2)` on both sides; rounding rows include 0.1-grid values (21.7, 22.35, 22.64, 22.65).
2. **Bare `false` text in v1 `vacation_active` (actioned in v2).** v1 line 362 `{% else %}false{% endif %}` renders the truthy string `'false'` when `vacation_off` is empty (memory `feedback_ha_template_bare_boolean_text_truthy_string`); masked only because the live instance sets the toggle. v2: `{{ expand(entity_vacation) | selectattr('state','eq','on') | list | length > 0 }}`, pinned by `test_vacation_empty_list_is_false` and `test_no_bare_boolean_text`.
3. **YAML comment carried the banned locale token (actioned).** The first draft's comment `strftime('%a') follows the system locale` tripped the `test_weekday_locale_safe` text pin — the pin is intentionally file-wide; comment reworded.

### P3 — polish / future-proofing
1. `mode: restart`: a `fan_change`/`boost_change` landing between `climate.set_temperature` and the notification step drops that tick's warmup push (the setpoint change itself is already applied). Accepted — bounded to one missed push per coincidence; the next transition pushes again.
2. Tuya cloud latency > 60 s on the setpoint attribute repeats the call and the push once. Accepted — not observed (09-07 history shows the attribute updating within seconds).
3. `blueprint/save` reloads the instance against the new schema a few seconds before the migrated config is POSTed; the instance reads `unavailable` in that gap. Accepted — same path as the ventilator deploy; the script asserts `on` afterwards.
4. Windows are evaluated per calendar day: a next-day-anchored hold-until runs until midnight only. Documented in the input description and the requirements doc; all four live slots end before midnight.
